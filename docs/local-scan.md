# Local Scan, utility accounts, and account roles

Local Scan is in **Intel** at `#local-scan`. Paste one pilot name per line or fleet clipboard rows with the pilot name first. Names are deduplicated case-insensitively. Reports support up to 2,000 unique names and use public ESI name resolution and batched current-affiliation lookups. No private character token is used to analyze the pasted pilots. Unresolved names and unavailable affiliations are explicit; unavailable membership is never classified as “No alliance.”

Results group alliances and their corporations into responsive columns, with organization logos, character counts, expandable pilot lists, and character zKillboard links. Simple result search and Advanced character/corporation/alliance name conditions support contains, starts with, ends with, and equals. Advanced conditions are combined with AND and filter the current snapshot; the PDF exports the full report.

Choose an optional solar system from search before generating. System, creator account name, generation date, version, affiliations, and highlight markings are saved in the report. **Set Destination** lists only the viewer's own linked characters with a current `esi-ui.write_waypoint.v1` authorization. Select one or more recipients; existing waypoints are appended unless the user explicitly chooses replacement. Each recipient has an independent success/error result. A dedicated SSO link requests waypoint access without the ordinary private-data scope bundle. Signing in and Navigation permission are required for this game-client action, even on a public report.

## Public reports and retention

Generating a report deliberately creates a public URL with a cryptographically random 256-bit token (`#local-scan/{token}`). Public JSON/PDF reads do not require an account. The public page avoids account/asset bootstrap calls; public responses request no caching or search indexing. These links contain the pilot list, public affiliations, creator display name, system, date, and red organization markings. They contain no credentials, private ESI data, or the creator's complete highlight list.

Retention choices are **30m, 1h, 2h, 12h, 24h, 3days, 7days, 30days, permanent**, defaulting to 24h. Lifetime starts when generation completes. Expiry is enforced on every JSON/PDF read, including after PDF rendering, and expired snapshots are physically removed by a once-per-minute cleanup task. Permanent reports remain until deleted. Open public pages revalidate access every minute. Already downloaded copies cannot be recalled.

The PDF uses small EQM and organization logos, creator/date/system/count metadata, the full hierarchy and pilot list, red markings, pagination, and **Generated by EVE Quartermaster v{generation version} by {generating account}**. Logo retrieval is best effort and bounded; unavailable logos do not prevent a complete text/count export.

Report-management scope is enforced on the server for every deletion mode:

- Authenticated users manage their own reports.
- Directors also manage reports attributed at generation to their linked corporations. Corporation selection is restricted to the creator's own linked-character corporations; a personal report has no corporation attribution.
- Admins and hosts manage any report.

Delete individual reports, selected reports, a generation-date range, or all reports in the permitted scope. Dates are UTC, start inclusive/end exclusive. The UI presents a review step before permanent deletion. Bulk calls never exceed the actor's scope, even if supplied IDs belong to someone else. Deletion removes public/PDF access as well as stored snapshots. Local Scan section permission is required to create or manage reports.

## Saved organization highlights

Each user can save up to 200 exact corporation/alliance names, resolved to stable EVE IDs. Add/remove controls update only that user's saved list, which persists between sessions. Signed-in Local Scan results and D-Scan linked local lists immediately reapply the current preferences, including when opening an older report. Adding or removing a match updates organization names, pilot names and counts without another ESI lookup. Alliance matches mark its corporations/pilots and counts red; a corporation match marks that corporation's pilots/count only. Public links and PDFs retain the markings present at generation, so later preference edits do not rewrite shared history. If the private view differs, a visible notice explains that generating a new report saves the current markings for sharing/export. [D-Scan](dscan.md) reuses these preferences for linked local lists; ordinary directional-scan ship names do not establish ownership.

## Roles and ESI privacy

**Intel Analyst** grants Navigation, Intel Reports, Local Scan, and Battle Reports. Navigation and Market are available by default to every role, including Applicant and Quartermaster, subject to account/global section settings. Quartermaster retains restricted mutation access, with explicit exceptions for Navigation analysis/lookups, Market appraisal, selected-character waypoints, and its scoped oversight refresh.

Admins can assign multiple roles using the account role checkboxes, or select several roles during account creation/invitation. Section permissions are the union of all assigned roles, including custom-role defaults/overrides. An Allow in one role is sufficient even if another role denies that section. Per-account overrides are applied after the union; globally disabled sections remain disabled. Existing host/admin always-visible rules remain. Removing a role removes its grants on subsequent API requests; reload the app to refresh the sidebar. Highest rank is retained in the legacy `role` field for compatible clients; `roles` contains the complete assignment list. Only hosts can assign Host, and the last-host safeguards apply to the complete assignment set.

ESI consent requests and collection use the combined permissions of the **token owner**, not the staff member requesting a sync. Accounts with only Intel Analyst/Quartermaster or utility-only custom permissions request identity by default, with optional navigation/waypoint scopes. They are not automatically enrolled in assets, skills, wallets, industry, PI, or other private character collection. Existing broad authorizations are filtered on use and access-token refresh is downscoped to permitted grants. Owner-policy checks also exclude utility accounts from Quartermaster oversight/Sync All. A separate Member or other collector role can legitimately enable private datasets; adding a utility role does not suppress permissions from a collector role. Explicit applicant recruitment consent retains its separate workflow. This change does not delete historical private records or revoke an authorization at CCP; users may re-link or revoke legacy consent there.

## SDE totals and rollout

Settings now lists stored totals and current/last-import counters for all import-stat fields, grouped into Inventory, Universe, Dogma, Blueprints, and PI. Detail counters cover celestial kinds, effect modifiers, default effects, recipe products/materials, and schematic inputs/outputs. These are processed-row counts, not guessed completion percentages. Unsupported activities are reported as skipped; missing last-run values display a dash.

Deploy backend/frontend together with `alembic upgrade head`: **0090_local_scan_reports** adds report/highlight tables and **0091_multiple_account_roles** adds role assignments/invitation role lists. The backend adds pinned ReportLab 5.1.0 and a small bundled EQM logo. No production data, live game waypoints, or live roles were modified during development. D-scan is implemented separately and requires migration 0092_dscan_reports. Battle-report retention/PDF enhancements remain planned.

## System summary and pilot portraits

The result header shows the saved system (or Not specified) and **Total pilots** from unique pasted names, including unresolved names. A resolved/unresolved split appears when necessary; this is a pasted snapshot, not a live system population query. Filtering the organization list does not alter that total. Expanded corporation lists show 24px EVE portraits beside pilot names. Both portrait and name links open the pilot's zKillboard character page in a new tab; unavailable portraits use a small placeholder. Public reports and D-Scan's linked local list use the same component. PDF exports repeat the system and total in the branded header on every page, with resolved/unresolved counts and generation metadata.
